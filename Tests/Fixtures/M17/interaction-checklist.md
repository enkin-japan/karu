# M17 交互与安全写入清单（真实窗口）

来源：方案 §13「交互与安全写入」、§5.1、§5.5、§5.6。每项都在真实 Karu 窗口里手动执行，
不能用单元测试或静态快照代替。「目标行为」是 M17 完成后的期望；「基线观察」在 T17.0 用
当前版本（v0.12.0 代码）实测后填写，T17.15 再用候选版逐项复测。

记录约定：基线观察写实际现象（例如「弹出系统补全列表」「插入 userCountunt」），
无法复现时写明环境与原因，不留空白结论。测试文件可用 `Tests/Fixtures/M17/completion/`
下的样本；语言、输入法和模块开关写进步骤里。

## 接受与收起

| id | 步骤 | 目标行为 | 基线观察 |
|---|---|---|---|
| ACC-01 | Python 文件中键入 `user_c` 弹出候选，按 Tab | 接受选中项，替换整个标识符；弹窗收起 | |
| ACC-02 | 同上，按回车（主键盘与小键盘各一次） | 接受选中项；不额外插入换行 | |
| ACC-03 | 同上，双击列表中的第二项 | 接受被双击的项 | |
| ACC-04 | 弹窗打开时按 Esc | 只关闭弹窗；不弹出系统补全列表，文本不变 | |
| ACC-05 | 弹窗未打开时在编辑区按 Esc | 不唤起任何候选，也不弹出系统补全列表（§5.1、§14.5） | |
| ACC-06 | 弹窗未打开时按 ⌥⎋ | 走 `complete(_:)`，弹出 Karu 的候选（允许空前缀，只列本作用域少量结果）；不出现系统列表 | |
| ACC-07 | 「编辑」菜单 →「显示候选」，再在快捷键设置里改键后用新键 | 弹出 Karu 候选；不占用 ⌃Space | |
| ACC-08 | 弹窗打开时按 ↑ / ↓ | 在列表中移动选中项，插入点不动 | |
| ACC-09 | 弹窗打开时按 ⌘↑ / ⌘↓ / ⌥↑ / ⌥↓ | 收起弹窗，按键交给编辑器（跳到文档首尾 / 按段落移动） | |
| ACC-10 | 弹窗打开时用鼠标点击正文别处 | 收起弹窗并取消旧请求；不接受任何候选 | |
| ACC-11 | 弹窗打开时按 ← / → 或点击把光标移到别处，再按回车 | 光标移动即收起；回车只插入换行，不写入过期候选 | |
| ACC-12 | 弹窗打开时切到其他 App（编辑器失焦），再切回 | 失焦即收起；切回后不自动重现 | |
| ACC-13 | 弹窗打开时滚动，使锚点离开可见区域 | 收起弹窗 | |
| ACC-14 | 弹窗打开时用菜单或工具栏切换语言 | 收起弹窗；下一次请求立即使用新语言的分析结果（§1 切换语言缺陷） | |
| ACC-15 | 继续键入使列表刷新，期间用 ↓ 选中第三项 | 刷新后按候选身份保留选中项，不按行号换成另一个候选 | |
| ACC-16 | 键入后按回车换行 | 收起弹窗 | |

## 安全写入（替换范围、撤销、文本边界）

| id | 步骤 | 目标行为 | 基线观察 |
|---|---|---|---|
| SAFE-01 | 光标在词中间：文本 `userCo│unt`（│ 为光标），接受 `userCount` | 替换整个标识符，结果为 `userCount`，不是 `userCountunt` | |
| SAFE-02 | 接受一个候选后按 ⌘Z 一次 | 一次撤销恢复接受前的原文，不与之前的键入合并成一步 | |
| SAFE-03 | 接着按 ⇧⌘Z | 重做恢复接受后的文本，光标位置正确 | |
| SAFE-04 | 在含 emoji 的行（如 `let 🎉count = 1` 之后）键入并接受候选 | UTF-16 范围正确；不截断代理对，不吃掉或复制 emoji | |
| SAFE-05 | 在含组合字符的行（如 `café`，e + U+0301）后键入并接受 | 组合字符保持完整，替换范围不落在字素中间 | |
| SAFE-06 | CRLF 换行的文件中在第 3 行键入并接受，再保存 | 只替换标识符；保存后行尾仍为 CRLF，没有混入 LF | |
| SAFE-07 | 文件末尾没有换行，在最后一行末尾键入并接受 | 接受正常；保存后末尾仍无换行 | |
| SAFE-08 | 空文档（新窗口）键入两个字母 | 不崩溃；没有可用词时不弹出 | |
| SAFE-09 | 折叠一个函数，在折叠行之后键入并接受；再在折叠头所在行键入 | 接受不展开、不破坏折叠；弹窗位置贴着可见的光标 | |
| SAFE-10 | 粘贴约 1 MB 文本后立即键入 | 粘贴后首次候选不卡顿（记录时延）；候选反映新文本 | |
| SAFE-11 | ⌘F 搜索出高亮后，在高亮行附近键入并接受 | 搜索背景高亮与语法前景色、候选弹窗共存，互不清除 | |
| SAFE-12 | JS 文件中 `const total = (a + b)` 之后键入 `tot` | 候选类别显示为「局部」，不是函数 | |
| SAFE-13 | 文件里同时有 `URLValue` 与 `urlValue`，键入 `url` | 两种拼写都保留，精确大小写的 `urlValue` 在前 | |

## 输入法（真实 IME）

| id | 步骤 | 目标行为 | 基线观察 |
|---|---|---|---|
| IME-01 | 简体拼音：在 Python 注释或代码里输入 `ceshi`（组字中） | 组字期间 Karu 弹窗不出现，不遮挡输入法候选窗 | |
| IME-02 | 拼音组字中按 ↓ / → 翻页、按数字选词 | 方向键和数字全部交给输入法，Karu 不拦截 | |
| IME-03 | 拼音组字中按回车提交原文字母 | 输入法提交拼音字母；Karu 不把回车当作接受候选 | |
| IME-04 | 拼音组字中按空格选词 | 输入法提交汉字；提交后不立即弹出 Karu 候选 | |
| IME-05 | 拼音组字中按 Tab / Esc | 交给输入法处理（Esc 取消组字）；不弹出系统补全列表 | |
| IME-06 | 日文罗马字：输入 `nihongo`，空格变换、方向键切换候选、回车确定 | 全程 Karu 不弹窗、不拦截按键；确定后文本正确 | |
| IME-07 | 日文输入法下用 ⇧+方向键调整文节后回车 | 文节调整正常，不触发 Karu 列表 | |
| IME-08 | 先打开 Karu 弹窗，再切到中文输入法开始组字 | 组字开始即收起 Karu 面板 | |
| IME-09 | 提交中文后切回英文输入法，先键入空格或换行，再键入 `user_c` | Karu 候选正常弹出并可接受（中文后直接接英文时两者连成一个标识符，不弹，T17.15c 用户确认合理） | |
| IME-10 | 全屏窗口里重复 IME-01～IME-04 | 与非全屏一致（已知草稿本全屏候选窗限制见 DEVELOPMENT.md，编辑器窗口单独记录） | |

## 模块开关组合

在「设置 → 模块」里切换；每种组合都打开 `Tests/Fixtures/M17/completion/scope/py_params.py`，
滚动、键入 `user_c`，再关闭窗口。

| id | 步骤 | 目标行为 | 基线观察 |
|---|---|---|---|
| MOD-01 | 全开（高亮、补全、类型推断、跨文件索引） | 着色、候选、成员候选都可用 | |
| MOD-02 | 只开高亮 | 着色正常；键入不弹任何候选；补全状态已释放 | |
| MOD-03 | 只开补全 | 无语法色；候选可用（作用域候选仍正确） | |
| MOD-04 | 只开类型推断 | 无着色、无弹窗；推断层不单独常驻（依赖补全才有使用者，记录实际内存） | |
| MOD-05 | 只开跨文件索引 | 无着色、无弹窗；索引照常建立，只服务导航（记录实际行为） | |
| MOD-06 | 全关 | 无着色、无候选；`isRuntimeStateReleased` 语义保持，新增状态全部释放 | |
| MOD-07 | 弹窗打开时关闭「补全」模块 | 弹窗立即收起，状态释放；重新开启后下一次键入正常弹出 | |
| MOD-08 | 键入过程中关闭「高亮」再开启 | 关闭时清除全部前景色；开启后视口重新着色，与关闭前一致 | |
| MOD-09 | 草稿本里键入 | 草稿本保持既不高亮也不补全（§3 模块开关） | |
