# Karu 高亮、补全与代码理解方案（M17）

2026-11-13 · 统整稿，第 15 节确认后开工 · 源码基线 `b106455`

**本里程碑要解决三个问题：**
- **读代码时**，跨行注释、字符串和嵌入代码始终染对。
- **写代码时**，正在编辑的函数的参数和局部变量排进候选前三。
- **点号之后**，能根据推断出的类型、导入的模块和项目里其他文件，给出可信的成员与名字。

这些功能共用两层分析，都在 Karu 进程内完成，不启动任何外部语言服务：
- **文档分析**：由编辑窗口持有，包括词法状态、声明与作用域、类型推断。
- **工作区索引**：应用级共享，包括导入解析和跨文件符号。

高亮、补全、类型推断、跨文件索引各自可以单独开关。实现继续使用 Swift、AppKit、TextKit 1 和共享的 `LineIndex`。深层推断所需的解析器经实测后选型（第 8 节）。

本文的「候选」指键入时弹出、可用方向键选择的补全列表。对标对象是 VS Code 的着色、匹配、排序、触发和接受体验，以及它在不启用语言服务器时做不到的成员提示。AI 整行续写不在范围内。[架构与预算](ARCHITECTURE.md) · [VS Code IntelliSense](https://code.visualstudio.com/docs/editing/intellisense) · [VS Code 语法高亮](https://code.visualstudio.com/api/language-extensions/syntax-highlight-guide)

## 2. 产品边界

- **做**：
  - 在 Karu 进程内完成的代码理解：词法、声明与作用域、类型推断、导入解析、跨文件符号索引。
  - 据此做的着色、候选排序、成员提示，以及符号导航里的工作区符号搜索。
- **不做**：
  - LSP 和任何外部语言服务进程。
  - 执行项目代码来获取信息，包括运行解释器读取路径，以及加载项目里的插件或配置脚本。
  - 跨文件重命名、全项目诊断与报错、代码格式化。
  - 跳转到定义，本里程碑先不做（第 14 节）。
- **预算**：所有分析都计入 Karu 自身的常驻内存，受 99 MB 红线和第 11 节各项上限约束。超出预算时按第 11 节的降级顺序退让，不能靠放宽红线解决。
- **说明依据**：每个候选都要能说明来源：哪一行的声明、哪一处接收者用法、推断出的哪种类型、哪个模块，或哪个文件。

## 3. 文档分析：所有权、版本与调度

一段文字是否属于代码、哪些名字出现在声明位置、光标处是哪种语言，对着色、候选和推断是同一个问题。新增一个由编辑窗口持有的文档分析对象（暂名 `DocumentAnalysis`），按需提供四层数据。

| 数据 | 使用者与保留时长 | 失效与释放 |
|---|---|---|
| 词法检查点：语言、文档版本、定界符栈、嵌套深度、当前子语言 | 高亮、补全、推断都用。约每 64 KB 保存一个稀疏检查点，每个几十字节，10 MB 文档约 160 个。token 只在着色或查询光标上下文时临时产生，不常驻。 | 编辑时丢弃受影响的最早逻辑行之后的检查点，并考虑 CRLF 的合并与拆分；之前的检查点保留。这同时取代两处现状：Python 每次编辑都清空检查点，以及通用多行定界路径每次绘制都从偏移 0 扫起。 |
| 声明与作用域 | 高亮读名字的类别；补全读名字、类别、位置和作用域；导航读位置。全文声明表每个版本只扫描一次；当前函数的参数、遮蔽和邻近成员在光标附近按需提取。 | 每个版本只调度一次扫描，并发布不可变的结果。删除或改名声明、粘贴、撤销、切换语言都会推进版本；旧结果要重新核对后才能显示或写入。最后一个使用者离开时释放。导航优先复用当前版本的声明快照（高亮或补全开启时一定有）；两者都关闭时才在打开时临时扫描、关闭即释放（T17.1 起）。 |
| 语法树与类型推断结果 | 只供补全的成员提示和着色的语法角色使用。模块级摘要（顶层名字、签名、类的成员）常驻；函数体内的推断只针对光标所在函数和它用到的函数，按需计算。 | 编辑只让受影响的顶层声明失效。函数体推断结果放在有字节上限的 LRU 中。关闭类型推断开关时释放全部。 |
| 文档词、候选匹配集、最近接受记录 | 只有补全使用。普通词保留原拼写；最近接受记录以窗口为范围，最多 32 项，关窗即释放。 | 刚输入的新名字先用小范围即时扫描补进来，再由去抖扫描校正整份词表。不记录普通词每一处出现的位置。 |

**版本与切换语言**：
- 文档版本由窗口在每次字符编辑后递增；切换语言和改变模块开关也会推进版本。
- `applyLanguage` 是语言切换的唯一入口，它让所有分析同时失效并重建，修复第 1 节的切换语言缺陷。

**调度（决策 D）**：
- 键入后，先用当前行和最近的检查点得到最新前缀，立即返回当前作用域里能确认的候选。远处的声明、推断和普通词随后分片补充。
- 每片在主线程上限时约 4 ms，用完就让出 run loop，正在输入的窗口优先。
- 每个任务携带文档版本、语言和窗口身份；新输入、关窗或切换语言都会取消旧任务。
- AppKit 的文本和布局操作留在主线程。只有实测证明分片仍超出第 11 节的时延目标时，才把有界、不可变的文本片段交给后台，并分别报告复制成本和峰值。

**模块开关**：
- 现有的「高亮」「补全」之外，新增「类型推断」和「跨文件索引」两个开关，默认开启。
- 关闭任何一个，都释放它独占的状态。
- 依赖关系：推断依赖词法和声明层；索引的结果只交给补全、推断和导航使用。四个全关时，新增状态全部释放，`isRuntimeStateReleased` 的语义保持不变。
- 草稿本目前既不用高亮也不用补全，本里程碑不改这一点。

**可移植性约束**：词法扫描器、声明提取、解析器和推断器必须是不依赖 AppKit、不持有共享可变状态的纯值类型代码（满足 Swift 6 的 `Sendable` 检查）。当前文档在主线程分片调用它们，工作区索引和导入摘要在后台队列调用同一份代码，两边结果一致。

## 4. 通用词法扫描器（决策 C）

各语言提供一份声明式的**词法档案**，交给同一个扫描器执行。扫描器有两种模式：
- **只推进状态**：用于检查点和跳转。
- **输出 token**：用于着色、光标上下文和语法树构建。

逐行的正则规则继续负责关键字、数字等单行内容，但只在扫描器判定为代码的片段里生效。

档案能表达的结构：
- 行注释前缀；块注释的起止符，以及是否允许嵌套。
- 字符串定界符：是否允许跨行、转义字符，以及原样字符串（不处理转义）。
- 插值的入口与出口，例如 JS/TS 的 `${…}`、Swift 的 `\(…)`、C# 的 `{…}`、Bash 的 `$(…)` 和 `${…}`。插值内部按代码处理，并追踪括号深度。
- 带自定义结束符的原样字符串，例如 Rust `r#"…"#`、C++ `R"d(…)d"`、C# `"""…"""`、Swift `#"…"#`。

| 语言 | 跨行结构 |
|---|---|
| C、C++、Java、C#、Go、CSS、SQL | `/* */` 块注释；C++ 原样字符串；C# 逐字字符串、原样字符串和插值；Java 文本块 `"""`；Go 反引号原样字符串 |
| JavaScript、TypeScript | 块注释；模板字符串与嵌套 `${}`；正则字面量（需要根据上一个 token 判断 `/` 是正则还是除号） |
| Swift、Rust | 可嵌套的块注释；Swift `"""` 与插值；Rust 原样字符串，以及可以跨行的普通字符串 |
| Python | 已有 `PythonTokenizer`（三引号、f-string）。迁移到通用扫描器前，必须先通过现有全部 Python 测试；否则保留原实现，只接入共享检查点。 |
| HTML、XML/plist | `<!-- -->`；XML 的 CDATA；HTML 的 `<script>` / `<style>` 进入子语言（第 7 节） |
| Bash、YAML、TOML | Bash heredoc（`<<EOF`、`<<-EOF`、带引号的结束符）和跨行引号；YAML 块标量（以缩进结束）；TOML 的 `"""` 与 `'''` |
| Markdown | 围栏代码块（字符、长度、语言别名和结束条件），进入子语言 |
| JSON、JSONL | 无跨行结构，保持现状 |

**什么时候妥协**：
- 某个结构档案表达不了，或者档案能表达但在第 13 节的边界样本上做不到全部正确：为该语言补一个只处理这一种结构的钩子函数，例如 heredoc、YAML 块标量、JS 正则。
- 钩子也无法在时延目标内通过样本：才退回该语言专用的 tokenizer。
- 每一次妥协都记入台账，写明语言、结构、原因和样本。

**接口（T17.2 定稿，main）**：
- `LexicalProfile`（纯值、`Sendable`）：行注释前缀；块注释（起止符、可否嵌套）；字符串形式（可选前缀、定界方式、是否跨行、转义字符、双写结束符即转义、插值列表）；原子 token（单行正则，如 Rust 字符字面量与生命周期，防止 `'"'` 被当成字符串开头）。
- 定界方式四种：固定起止符；同一引号连写 N 个并以同样长度结束（C# 原样字符串）；前导符加 N 个 `#`（Rust `r#"…"#`、Swift `#"…"#`，Swift 的转义和插值也带同样数量的 `#`）；C++ `R"d(…)d"`。
- 状态 `LexicalScanState`：帧栈（块注释及嵌套深度、字符串及解析出的结束符、插值及括号深度），上限 64 层，可比较、可存入检查点（`LexicalState.generic`）。帧是枚举，T17.3 的钩子增加新帧种类时检查点格式不变。
- `LexicalScanner` 对 `NSString` 的任意 `[from, to)` 工作，不要求按行切分，为第 6 节的超长行分片留出接口：`advance` 只推进状态；`segments` 输出代码、字符串、注释、插值边界四类片段。
- `LanguageDefinition` 增加可选的 `lexicalProfile`。有档案的语言，正则规则只在代码片段里生效，并跳过 `.string`、`.comment` 类规则，字符串和注释以档案为准；没有档案的语言（JSON、JSONL，以及 T17.3 前尚未接入的语言）保持逐行规则。
- 删除 `multilineStringDelimiters` 与 `openMultilineDelimiter` 这条从偏移 0 起扫的路径。高亮按「最近检查点 → `advance` → 视口 `segments`」取得状态。
- 试点：T17.2 接入 JavaScript、TypeScript、Rust 来验证档案，其余语言在 T17.3 接入。
- **超长行（T17.2b）**：扫描器 `advance` / `segments(…stoppingAtSafePointFrom:)` 返回目标之后第一个安全切点（token 边界，不在代理对、标识符、CRLF 中间，代码里前一单元不是可回看的前缀字符）。行长超过 `longLineThreshold`（8192）时色带停在行内，长行内部也记检查点。JSON/JSONL 用只含字符串的档案，键由 `propertyStringFollower` 判定。
- **T17.3 通用扩展**：`LexicalProfile.keepsStringRules`（HTML/XML 属性值、C `#include <…>` 仍走 `.string` 规则）；`AtomForm.precededBy`（`AtomContext`：往回跳过空白看前一字符或单词，只读文本，JS 正则与除号的判定）。
- **T17.3b 行块钩子**：`lineCommentPrecededBy`（行注释的前置字符）；`StringForm.precededBy` + `AtomContext.lineStart`（字符串开头的文本上下文）；`lineBlocks`（`.heredoc` / `.indentedBlock` / `.fence`，正文报告为 `LexicalSegment.block(kind)`，帧带 `inBody`，开头行剩余部分仍是代码）；`keepsCommentRules`（Markdown 借注释色的规则）。

## 5. 候选怎么选、怎么排

### 5.1 请求与触发

- **普通输入**：保留两个字符的门槛，由字母或下划线触发；JS 的 `$` 视为标识符字符。
- **手动唤起**：
  - `EditorTextView` 重写 `complete(_:)`，转给 Karu 的补全控制器，系统默认的 ⌥⎋ 因此直接可用。
  - 「编辑」菜单增加「显示候选」，接入现有的快捷键设置，用户可以改键。
  - 不占用 ⌃Space，它是 macOS 默认的输入法切换键。
  - 手动唤起允许空前缀，只列出本作用域内的少量结果。
- **Esc**：
  - 弹窗打开时，Esc 关闭弹窗；弹窗未打开时，不唤起候选。
  - T17.0 实测 Esc 现在不会弹出系统列表；重写 `complete(_:)` 后要回归确认 Esc 仍然不进入 Karu 的候选。
- **触发字符**：
  - 点号后允许零前缀，前提是有推断类型、模块解析结果或接收者证据之一；三者都没有就不弹出。
  - 之后再按语言加入 `?.`、`->`、`::`。
- **字符串与注释**：
  - Python f-string 和 JS 模板的插值表达式内，按代码处理。
  - 普通字符串和注释内默认不弹出，手动唤起时给文档词。
  - Plain Text 保持现在的文档词体验。

### 5.2 候选模型与来源

每个候选带有显示名、插入文本、类别、来源、替换范围和稳定身份。按作用域就近原则处理同名遮蔽；可信度低的全文件名字只作为后备。分析时跳过字符串、注释和其他子语言。

| 语言 | 作用域与声明 | 类型推断 |
|---|---|---|
| Python | 完整：函数参数（包括带括号的默认值和类型注解）、局部赋值、循环目标、`with`/`except`/`import` 别名、推导式变量。作用域由缩进确定。 | 深层（第 8 节） |
| JS/TS | 完整：函数和箭头函数的参数、`const`/`let`/`var`、解构、`catch` 参数、`for` 的绑定。作用域由括号确定，括号匹配依赖词法状态。箭头绑定必须看到 `=>` 才算函数，修正 `const total = (a + b)` 被当成函数的问题。 | 深层（第 8 节） |
| Swift、Go、Rust、Java、C#、C、C++ | 基础版：当前函数的参数和函数体内的局部声明，作用域由括号确定。 | 只用显式声明的类型：成员来自本文件和工作区索引里同名类型的声明（第 8 节） |
| Bash、SQL、数据格式 | 只用文档词。 | 无 |

**接口（T17.4 定稿，main）**：
- 声明只从代码 token 中提取：按语言族手写遍历器，读通用扫描器的代码片段（Python 分析用 `PythonLanguage.analysisProfile`，着色仍用 `PythonTokenizer`）。
- `DeclarationScan` 保持一次扫描、多处共用：细分声明种类（参数、导入、方法等），映射回旧三类供着色和导航；作用域大纲用紧凑字节流存起止范围与种类，声明归属按位置推出。
- 查询：`visibleBindings(at:)`（内层优先、同名遮蔽、按语言规则）和 `scopeChain(at:)`。偏移对应快照的版本，编辑后的映射与模块级绑定缓存由 T17.5 负责。
- `DeclarationScanner` 可分步推进，`DocumentAnalysis` 按 4 ms 分片运行，版本变化即作废。

### 5.3 排序

1. **按位置过滤**可用的候选。
2. **比较匹配质量**：原大小写前缀 > 忽略大小写前缀 > 驼峰或下划线词首 > 有界的宽松模糊匹配。
3. **匹配质量相同时按来源**：当前函数的参数和局部绑定 > 推断类型的成员 > 本文件的声明 > 导入模块的成员 > 工作区其他文件的名字 > 语言关键字和内置名 > 普通文档词。
4. **仍然相同时**：依次按光标附近的使用、最近接受、稳定的字典序决定。距离只在当前函数或附近的小窗口内计算。
5. **控制计算量**：宽松模糊匹配只用于已经有界的候选集，避免敲一个字母就遍历全部文档词和索引。先排除无意义的项，再截取 50 个。
6. **复用匹配集**：继续输入时，复用同一版本的匹配集；退格、版本变化或上次结果被截断时，重新取候选。

### 5.4 成员候选

成员候选按可信度从高到低取：

1. **推断出的类型**：取类型的成员，来源包括内置类型表、本文件和导入模块的类声明、工作区索引。
2. **`self.` / `this.`**：取当前类的字段和方法。
3. **同一绑定此前的用法**：`obj.` 取当前作用域内同一绑定之前出现过的 `obj.name`。绑定被遮蔽、重新赋值或接收者不明时，降低可信度。

一旦有可信的类型，就不再把仅凭用法观察到的名字混进来。反例：`order.` 和 `user.` 都有 `id`，但两个对象的其他成员不能互相推荐。

### 5.5 选中、显示与接受

- **列表显示**：
  - 每行显示名称和简短类别，如「参数」「局部」「成员」「模块」「文件」「文档词」。成员和函数附带推断出的类型或签名摘要。
  - 文案提供中、英、日三语。
  - 弹窗宽度按内容自适应并设上限，不再固定为 240。
- **列表刷新**：按候选身份保留用户主动选中的项，不再按行号保留，避免同一行换成另一个候选。
- **接受**：
  - 接受前重新核对光标、版本、两侧的标识符和选区，过期就重算或收起。
  - 替换整个标识符，继续走 `insertText(_:replacementRange:)`。
  - 一次撤销就能恢复原文，不与之前的键入合并成一步。
- **字符边界**：取词和扫描使用统一的 Unicode 标识符边界，按语言处理 JS 的 `$`、组合附加符号和非 BMP 字符。所有写回范围都用 UTF-16。

### 5.6 输入法与收起时机

- 组字开始时收起面板。在拦截按键之前、重新弹出之前，都检查 marked text。
- 以下情况收起面板并取消旧请求：接受候选、点击、换行、移动光标、编辑器失焦、切换语言、滚动导致锚点离开可见区域。
- 中文和日文都用真实输入法分别验证选词、翻页和回车提交，然后切回英文继续写代码。
- 现有的上方弹窗和空间不足时的下方回退继续使用。

## 7. 嵌入语言

- **HTML**：普通的 `<script>`（含 `type="module"`）和 `<style>` 进入 JS 和 CSS 子语言；其他 `type` 的 script 按普通文本处理。
- **Markdown**：
  - 识别围栏的字符（`` ` `` 或 `~`）、长度、语言别名和结束条件，按需加载子语言；未知语言按普通代码块处理。
  - 这一项取消 T14.5「代码块按语言高亮搁置」的决议。
- **JSX/TSX**：只做标签、属性和 `{}` 表达式三类边界，不做组件属性的成员推断。
- **作用范围**：
  - 光标所在的子语言决定候选词表和点号触发。离开代码块后回到宿主语言，标题栏的文档语言保持不变。
  - 子语言片段只做词法、作用域和浅层推断，不做导入解析。

**接口（T17.8 定稿，main）**：T17.8 分三步交付，每步单独提交。
- **T17.8a 宿主内嵌子语言（扫描器层）**：
  - 嵌入由通用扫描器原生处理，不另起一套扫描器。`LexicalProfile.embeds` 声明宿主可进入的子语言表（下标从 1 起，0 表示宿主自身），每项是子语言的标识符和它的档案；子档案在第一次进入时才编译，编译结果缓存在宿主扫描器里，扫描器仍是 `Sendable` 的值类型。
  - 状态：`LexicalScanState` 增加可选的子状态（子语言下标、子语言自己的 `LexicalScanState`），用装箱的不可变值保存，宿主帧栈不变，检查点格式仍是 `LexicalState.generic`。嵌套只有一层：子档案内的 `embeds` 不生效。
  - 片段：增加带语言下标的 `segments` 变体，回调多一个参数（0 为宿主）；原有 `segments` 签名保留，供不关心语言的调用方。
  - **HTML**：新增原始文本元素 `<script>`、`<style>`。开始标签用新帧跟踪（标签名、属性、引号、`type` 的取值），可以跨行；`>` 之后进入正文。正文的结束只看文本：第一个大小写不敏感的 `</script` / `</style`，后接空白、`/` 或 `>`，与子语言当时的状态无关（浏览器的语义）。`type` 缺省或为 JavaScript 类 MIME、`module` 时进入 JS；`<style>` 进入 CSS；其他 `type` 的正文按普通文本（plain）。JSON 类 `type` 是否进入 JSON，按 VS Code 基线决定。
  - **Markdown**：`.fence` 帧增加语言下标。开头行的信息串取第一个词，小写后查别名表；查不到时正文仍是 `.block(.plain)`。正文按行交给子语言，结束行的判定不变，仍由宿主负责。
  - Python 子语言使用 `PythonLanguage.analysisProfile` 计算状态，正文着色使用 Python 的代码规则，不走 `PythonTokenizer`。
  - 切分保证与安全切点对复合状态同样成立。在子语言里，安全切点等于子语言的安全切点，但不能落在结束标记中间；在宿主里则保持原有定义。
  - `LanguageDefinition.tokens` 对子语言片段使用子定义的规则和类别（代码规则、字符串规则、正则细分、插值边界类别、键判定）。子定义在第一次用到时才构建，并缓存起来。
  - 子语言片段的标识符只按子语言的全文符号表和默认类别着色，不用声明位置的角色。
- **T17.8b JSX/TSX**：在 JS 档案里用帧实现 JSX。在表达式位置（判定与正则相同，用 `AtomContext`），`<` 后接标识符或 `>` 时打开 JSX 元素。标签名、属性名、标签标点、属性字符串各报为对应类别；子元素文本既不是代码，也不运行规则；`{…}` 回到 JS 代码，并追踪括号深度。TS（`.ts`）不开 JSX。新增 `typescriptreact`（`.tsx`）：开 JSX，并排除泛型箭头 `<T,>` 和 `<T extends …>`。`.jsx` 归入 `javascript`，JS 始终开 JSX，与 VS Code 一致。
  - 实现时的取舍（T17.8b）：
    - 帧：`jsxTag`（标签内，带阶段）、`jsxText`（子元素文本）、`jsxExpression`（`{…}`）。同一棵树的嵌套元素只在一个帧里计深度；每个 `{…}` 压一帧。闭合标签按层数计数，不核对名字。
    - 着色按 VS Code 基线：小写字母加数字的标签名为标签色，其余（大写开头、含 `.`、`-` 等）为类型色，对应 `support.class.component`；`ns:name` 两段各自判定，`:` 不着色。`{` `}` 用插值边界色（VS Code 的 `punctuation.section.embedded`）。属性字符串为字符串色（浅色主题也是 `#A31515`，不同于 HTML 属性值）。子元素文本和标签内的空白、`=` 报为 `.plain`。
    - TSX 在表达式位置排除的类型参数表：`<T,`、`<T =`、`<T extends`、`<const T`，只在同一行内向后读。`<T>(…) =>` 仍是元素，与 TypeScript 在 `.tsx` 中的解析一致。标签名后的类型实参 `<Badge<string>>` 中，标识符为类型色。
    - 遍历器：标签、属性和文本以字面量 token 进入，`{…}` 以插值进入，所以不会从标记里产生绑定。
    - 补全位置：标签内和 `{…}` 为代码；属性字符串和子元素文本为字符串，不自动弹出。
- **T17.8c 光标处的子语言**：根据光标所在位置的语言（宿主或子语言），决定候选的关键字、点号触发、`$` 标识符、大小写规则和字符串、注释位置；JSX 子元素文本按字符串位置处理。子语言片段的声明和作用域由该语言的遍历器按片段运行，结果只供补全使用，不进入导航。离开代码块后回到宿主语言，标题栏的文档语言不变。
  - **细化（main，T17.8c 开工前）**：
    - 光标处的语言：由宿主帧决定。`rawText` 正文、带语言的 `.fence` 正文是子语言，其余（包括开始标签和未知语言的围栏）是宿主；位置类别取子状态（子状态为 nil 即初始状态）。
    - 候选请求的语言标识符取光标处的语言。子定义的关键字和内置名在第一次用到时构建并缓存，关闭模块时释放。
    - 声明：宿主有嵌入时，`DeclarationScanner` 把每个嵌入片段交给该子语言的遍历器（按语言懒建）。每个片段打开一个新的 `.embedded` 作用域，片段结束时关闭其中所有未闭合的作用域，所以一个片段的错误不会漏到下一个。同语言的各片段共享顶层（HTML 的经典脚本共享全局，教程里的同语言围栏相互接续）。片段内的声明只进作用域查询，不进导航，也不进文档级的符号集合，所以不会出现在宿主正文或别的语言的候选里。
    - 着色：子语言片段可以用快照里落在本片段的声明位置角色（按范围精确匹配），仍不用宿主的符号表。

## 8. 类型推断（决策 H、I）

### 8.1 范围

**深层推断：Python、JS/TS。**

| 能力 | Python | JS/TS |
|---|---|---|
| 显式类型 | 注解、`TypeVar` 与常见泛型（`list[T]`、`dict[K, V]`、`Optional`、`Union`）、`dataclass` / `NamedTuple` / `TypedDict` 字段 | 注解、`interface`、`type` 别名、类、基本泛型、联合类型、可选属性；JS 文件读取 JSDoc 的 `@type`、`@param`、`@returns` |
| 推断 | 字面量；容器字面量和 `append` / `add` 的元素类型；函数返回值（取各 `return` 的并集，限制调用深度）；`for`、`with` 和推导式绑定；`__init__` 中的 `self.x` 字段；`@property` | 字面量与对象字面量的形状；数组元素；函数返回值；`await` 解开 `Promise`；类字段；解构绑定 |
| 收窄 | `isinstance`、`is None` / `is not None`、真值判断 | `typeof`、`instanceof`、`in`、可选链与非空判断 |
| 内置类型 | 构建时从 typeshed 生成 `builtins` 和完整标准库的紧凑存根表，按模块懒加载 | 构建时从 TypeScript 的 ES 标准库和 DOM 声明生成紧凑成员表；DOM 部分只在用到浏览器全局对象时懒加载 |

**只用显式声明：Swift、Go、Rust、Java、C#、C、C++。**
- 局部变量、参数、字段的类型都写在声明里，所以只需读声明。成员来自本文件和工作区索引中同名类型的声明，包括 struct、class、enum、protocol、trait 和 Go 的方法接收者。
- 这些语言的标准库不建类型表。

**静态类型语言的实现（T17.11d，main 定）**：
- 读两样东西：声明快照（与补全共用的 `DeclarationQueryIndex`），以及声明附近的代码 token。不建语法树。
- 成员来自本文件里同名类型的主声明，以及 extension、`impl`、partial、Go 方法和 C++ 类外定义。
- 私有成员只在类型及其 extension 内列出。只有用 `T.` 或 `T::` 访问时，才列出 static 成员和不带 self 的关联函数。
- `->` 只用于 C/C++，`::` 只用于 Rust/C++。
- 签名摘要：Swift 和 Rust 写成 `(参数) -> R`，Go 写成 `(参数) R`；类型写在前面的 Java、C#、C、C++，统一写成 `(参数) : R`，与 VS Code 的 Java 补全一致。
- 推断不出就按未知处理，走用法证据。包括：标准库类型、泛型实参、闭包参数、循环变量、模式变量，以及其他文件里的类型（等 T17.14）。

**推断不出时**：
- 类型为未知，不猜，退回第 5.4 节的用法证据。
- 推断结果只用于候选、签名摘要和语法角色着色，不报错，也不做诊断。

**成员的精确度规则（T17.11b 实现）**：
- 只列出确实属于接收者类型的成员：类沿 MRO 取成员（自身声明在前，继承的在后，`_x` 再后，dunder 最后）；类对象只列类级成员加元类成员；模块列 `__all__`、公开名字和再导出。
- 联合类型只列每个非 `None` 成员类型都有的成员；`Optional[X]` 未收窄时列 `X` 的成员；只有 `None` 时不给推断成员。
- 联合里含未知、接收者未知、未约束的 `TypeVar`、未知装饰器的函数结果、相对导入或表里没有的模块（T17.13 前），都当作未知：不给推断成员，走用法证据。
- 有可信类型时，成员访问不再混入用法证据和文档词。
- 推断超出单次请求的预算（含语法快照更新，25 ms）时同样当作未知，光标留在同一个点号之后时不重试。

**JS/TS 的补充（T17.11c 实现）**：
- 类沿继承链取成员（自身声明在前，`extends` 的在后）；接口合并同名声明并沿 `extends` 取成员，`implements` 不带来成员。实例不列 `static` 成员和 `constructor`；类对象只列静态成员、`prototype` 和 `Function` 的成员。`private`、`protected`、`#x` 只在类体内列出。
- 可选成员（`x?: T`）照常列出，访问它得到 `T | undefined`，未收窄时与 `Optional[X]` 一样列 `T` 的成员；`?.` 和 `x!` 去掉 `null` / `undefined`。
- 索引签名（`[k: string]: V`、`Record<K, V>`）不列任意键：只有索引签名的类型没有可列的成员，走用法证据；`x['k']` 取 `V`。
- `any`、`unknown`、`object`、`{}`、解析不到的名字、`import`（T17.13 前，含表里没有的模块）都当作未知；联合里含未知同样当作未知。
- 对象字面量、内联对象类型和 JSDoc `@typedef` 按结构列出成员；交叉类型取各部分成员的并集。
- 已弃用的库成员（如 `trimLeft`、`substr`）排在其他成员之后，与 TypeScript 语言服务一致。
- 内置类型先查 ES 区段；只有文档里的名字在 ES 里找不到（如 `fetch`、`document`、`HTMLElement`）或 DOM 符号自身的类型文本才会读 DOM 区段。只用 ES 全局对象的文档从不读 DOM 区段。
- 嵌入的脚本（HTML `<script>`、Markdown 的 js/ts 围栏）不做推断，仍走用法证据；JSX/TSX 里的 `{expr.}` 照常推断。

### 8.2 解析器选型（依据实测）

深层推断需要完整的语法树。T17.9 用同一组样本比较两条路线，按下面的标准选型。

| 路线 | 包体（仅记录，不设限） | 优点 | 风险 |
|---|---|---|---|
| 手写解析器（Swift，基于第 4 节的通用扫描器输出的 token） | 预计几百 KB | 不新增依赖；与检查点、版本、分片调度天然一致；节点结构可以按内存需要精简 | 工作量大；需要容错（正在键入的代码多半语法不完整） |
| tree-sitter 运行时加 Python、TypeScript、TSX 三份语法 | 运行时约 0.2 MB，每份语法预计 1–3 MB，需实测 | 容错和增量解析成熟 | 新增 C 依赖；语法树内存要实测 |

**选型标准**（按顺序比较）：
1. 第 11 节的推断内存门槛。
2. 1000 行文件完整解析和键入后增量更新的时延。
3. 语法不完整时的容错样本通过率。

两条路线都达标时，选维护成本低的一条：新增依赖、构建复杂度和后续扩展到其他语言的难度。选型结论和数据记入台账，并同步更新 ARCHITECTURE.md §2 的「语法高亮」行。

**T17.9 实测方法（main，2026-11-15）**：
- **原型位置**：两条路线的原型都放在仓库外的 `/Volumes/enkin/project-support/KaruM17-ParserProto/`（`handwritten/`、`treesitter/` 两个独立 SPM 包），不进 Karu 的 Package.swift，也不提交。入选路线在 T17.11 正式实现。手写原型复制（不修改）KaruCore 的扫描器源文件，并记下复制时的 commit。tree-sitter 原型使用 tree-sitter 官方组织的运行时和 Python、TypeScript（含 TSX）语法，固定到发布标签，从 Swift 直接调用 C API。
- **语法树的范围**：覆盖推断要用的全部结构，即模块、类、函数（含参数和注解）、赋值和解构、导入、`return`、`for`/`with`/推导式绑定、调用、成员访问、下标、字面量、`await`、JSX 元素和表达式，以及 TS 的 interface、type、enum 和泛型。不做诊断。
- **同一组输入**：`Tests/Fixtures/M17/inference/sample_1000.{py,ts}`（多样名字），由它们拼接成的 10 MB 文件，以及 `Tests/Fixtures/M17/parser/` 的容错样本（缺括号、悬空的点号、半个关键字、未结束的字符串、缩进错误等，每个样本带光标标记和期望）。
- **容错的判定**：从语法树取出四项事实，即顶层名字、光标外层的类与函数链、最内层函数的参数、点号前的接收者表达式原文；四项都与期望一致才算通过。两条路线使用同一个比较脚本。
- **测量**（Release 构建，同机交替运行，报告负载）：
  - 1000 行样本：完整解析的中位数和 p95（各 50 次）。
  - 在文件中部插入一个字符后的增量更新：tree-sitter 用 `ts_tree_edit` 加重解析，手写路线用它实现的增量方式（至少按顶层语句重解析）。
  - 语法树常驻：`malloc_zone_statistics` 与 `phys_footprint` 的配对增量，1000 行样本和 10 MB 文件各测一次。
  - 包体增量：Release 二进制的大小差。
  - 构建复杂度：C 目标、Swift 6 严格并发、签名与公证的影响。

**T17.9 结论（main，2026-11-15）：选手写解析器。** 按选型标准逐项比较，手写路线在内存和时延上都明显领先，容错不输：
- 内存：1000 行的语法树分别是 0.1–0.6 MB 和约 1 MB；10 MB 文件分别是 34 MB 和 340–360 MB，tree-sitter 的整棵树无法常驻。
- 时延：1000 行完整解析约 0.3 ms 对 1.4–1.6 ms，增量约 0.02 ms 对 0.02–0.2 ms；10 MB 完整解析约 90 ms 对 500 ms。
- 容错：58/58 对 57/58。tree-sitter 只看语法树本身是 38/58，要靠一层约 730 行的恢复代码补到 57/58；另有一个样本（未结束的 f-string）丢掉了半个文件，在 tree-sitter 外面无法补救。
- 维护：手写路线不新增依赖，包体约 +0.3 MB；tree-sitter 包体约 +3.5 MB，且新增 C 依赖，语法升级时无法审阅 diff。手写路线的代价是代码量约 4,700 行，到产品质量还要 3–4 周（语法补全、容错打磨、接入调度），T17.11 承担这部分工作。
- 两个原型都在 `/Volumes/enkin/project-support/KaruM17-ParserProto/`，没有提交。手写原型作为 T17.11 的起点，tree-sitter 原型只作为对照数据保留。

**T17.10 接口（main，2026-11-15）**：
- **来源**（只用官方仓库，固定版本并校验哈希）：
  - Python：typeshed（`python/typeshed`），固定到某个 commit，取 `stdlib/` 全部存根。`sys.version_info` 按 3.13 求值，`sys.platform` 按 `darwin` 求值。
  - TS：`typescript` npm 包，固定版本并校验 integrity，取 `lib.es*.d.ts`（到 ESNext）和 `lib.dom*.d.ts`。
  - 源码缓存在仓库外的 `/Volumes/enkin/project-support/KaruM17-TypeSources/`，不进仓库。
- **生成**：
  - `scripts/m17/gen-type-tables.sh` 负责下载、校验，再调用生成器。Python 生成器用标准库 `ast` 读 `.pyi`；TS 生成器用 Node 跑 TypeScript 编译器 API，开发机现有 Node 即可，产品不依赖 Node。
  - 输出提交到 `assets/typetables/`。同样的输入两次生成的结果逐字节相同。
- **格式**：每种语言一个二进制文件，用 mmap 读取，只读、可跨线程共享。
  - 文件头加排序索引：Python 按模块名，TS 按全局符号名。DOM 符号放在单独的区段，只在查询到 DOM 符号时才触碰。
  - 条目内容：
    - 类：名字、基类、类型参数、成员。
    - 成员：名字、种类（方法、类方法、静态方法、属性、字段）、签名、类型。
    - 签名：参数名、参数种类、注解、是否有默认值，以及返回类型；重载全部保留，但有上限。
    - 模块级函数、变量、`__all__`，以及再导出（`from x import y as y`、`import x as x`）。
    - TS 另有：interface（含 extends、调用签名、构造签名、索引签名）、`declare var`、类型别名、命名空间成员（用限定名）。
  - 类型表达式规范化为文本，放进共享字符串表。
  - 同时提供一个小型 `TypeExpr` 解析器，支持 Python 和 TS 两种类型语法。生成时每条类型文本都必须能被它解析，T17.11 直接复用。
- **加载**：
  - `TypeTableStore`（`Sendable`）在第一次查询时 mmap 文件，解码结果缓存在有字节上限的 LRU 里，计入第 11 节第 ② 项。关闭补全模块时释放。
  - 表文件的查找顺序：App 包的 `Contents/Resources/TypeTables/`、环境变量 `KARU_TYPE_TABLES`、开发时按源码路径推出的仓库 `assets/typetables/`。
  - main 负责改 `bundle-macos.sh`，把表文件复制进 App 包。
- **许可证**：typeshed 和 TypeScript 的声明文件都是 Apache-2.0；DOM 声明另有 W3C/WHATWG 来源说明。全文和版本写进 `docs/THIRD-PARTY-NOTICES.md`。

**T17.11 拆分（main，2026-11-15）**：
- **T17.11a 解析器产品化**：
  - 把手写原型移进 `Sources/KaruCore/Parsing/`，直接使用 KaruCore 的扫描器。Python 一个解析器；TS/TSX 共用一个，JS 作为它的一种模式。
  - 接入 `DocumentAnalysis`，像声明快照一样按版本发布语法快照，按顶层语句分片构建，并根据编辑日志做增量更新。
  - 大小策略：不超过 1 MB 的文档保留整棵树；更大的文档只保留模块级摘要（各顶层语句的头部和范围），光标所在的顶层语句按需解析，结果放进有字节上限的 LRU。

### 8.3 内存与时延门槛

- **1000 行以内的文件**：推断（语法树、模块摘要、函数体推断缓存，以及该文件用到的导入摘要）带来的配对增量 ≤10 MB。用变量和类型都足够多样的样本实测，不用重复名字的夹具。
- **更大的文件**：只为整个文件保留模块级摘要，函数体只推断光标所在函数和它的直接依赖。LRU 有字节上限，内存增长与文件大小脱钩，上限见第 11 节。
- **时延**：成员候选的首批结果 p95 ≤50 ms，与第 11 节「按键提交到首批候选可见」同一口径。

## 9. 导入解析（决策 H）

**解析对象**：
- Python：`import a.b`、`from x import y`、相对导入、`__init__.py` 的再导出（深度上限 3）、`__all__`。
- JS/TS：ES `import`、`require`、`export … from`。

**查找路径。不执行任何程序，只读文件**：

| 语言 | 查找顺序 |
|---|---|
| Python | ① 文档所在项目文件夹的根（第 10 节）；② 项目内的 `.venv` / `venv`：读 `pyvenv.cfg` 推出 `site-packages`；③ Run 设置里该语言选中的解释器（Karu 托管、系统或自定义路径）对应的标准库和 `site-packages`，路径由解释器的安装布局直接推出。解释器的定位复用 Run 模块已缓存的结果（包括它已有的登录 shell PATH 读取），不为导入解析另启进程。`.pth` 文件只读取其中的路径行，`import` 行一律忽略，因为那会执行代码。标准库优先用内置的 typeshed 存根表（不依赖本机装没装 Python）；第三方包优先读 `.pyi` 存根，其次读 `.py`。 |
| JS/TS | 相对路径；从文件所在目录向上逐层查找 `node_modules`，不越出项目文件夹；读取 `package.json` 的 `types` / `typings` / `exports`，以及 `@types/*`；读 `.d.ts`，没有时读 `.ts` / `.js` 的导出。 |

**T17.13 定案（main，2026-11-15）**：
- 标准库模块名先走内置 typeshed 表，不读磁盘，排在查找顺序 ① 之前。项目里与标准库同名的文件（如 `json.py`）因此不会遮住标准库，这与 Pylance/Pyright 的做法一致。
- 导入在独立的串行 utility 队列 `dev.enkin.Karu.imports` 上执行。摘要到达后，如果光标位置、版本和编辑次数都没变，而且没有在组字，就刷新同一位置的弹窗。
- 开关的分工：typeInference 或 completion 关闭时，导入状态全部释放。crossFileIndex 关闭时，文档按「无项目文件夹」处理，标准库存根和路径 ③ 照常可用。

**结果形态**：
- 每个模块只生成导出摘要：顶层名字、类型或签名、类的成员。不保留模块的完整语法树。
- 摘要缓存在内存 LRU 中，有字节上限；超过上限的模块只保留名字列表。
- 单个源文件超过 2 MB 时，只取名字。

**无项目文件夹时**：未保存的缓冲区，以及不在任何项目文件夹里的文件，只解析内置的标准库存根和第 ③ 类路径（解释器自带的包），不读取文档所在的目录。这样不会触发 macOS 对「桌面」「文稿」「下载」的访问授权。读取同目录文件是否会触发授权，T17.0 实测；如果不会，可以放宽到同一目录。

**执行位置**：查找、读取和解析导入的模块都是磁盘操作，放在第 10 节的后台队列上执行，只有生成的摘要回到主线程合并。摘要到达之前，点号候选先用已有的信息，结果到达后再刷新。

**失效**：
- 项目内文件的修改由第 10 节的文件监听通知。
- `site-packages` 和 `node_modules` 按目录修改时间检查，不常驻监听。

## 11. 内存、时延与降级

**基线**：
- v0.12.0 发布记录：两轮均为 **32 / 51 / 63 MB**（空文档、约 1 MB JSON、约 10 MB Python），包体 **6.4 MB**。

## 13. 对照样本与通过标准

**高亮**：
- 关闭 VS Code 的语义高亮，用固定版本逐个样本比较 UTF-16 区间、语言和类别；有歧义的地方用 `Developer: Inspect Editor Tokens and Scopes` 核对。
- 指定的跨行、插值和围栏样本，边界必须全部正确。
- 每个样本都分别从文件头顺读、从中部跳入、编辑上游、撤销后读取。

[VS Code 颜色检查工具](https://code.visualstudio.com/api/language-extensions/syntax-highlight-guide#scope-inspector)

**候选质量**：
- 每个样本固定正文、光标、输入序列、期望候选和允许的来源。
- 至少 40 个作用域类标注位置，覆盖 Python、JS/TS、纯文本和负例，并预留一部分不参与调参的样本。
- 按类别报告：目标排第一、排进前三、在前五十里缺失的数量及分母；另外单列「不该弹出却弹出」的次数。
- 有明确局部变量目标的样本，前三命中率要 ≥90%。
- 输入法组字、伪声明、错误接收者是硬性回归项。

**类型推断与成员**：
- 至少 40 个点号位置，Python 和 JS/TS 各半，涵盖字面量、容器、返回值、类字段、收窄、泛型和语法不完整的代码；再加 10 个静态类型语言的显式声明样本。
- 精确度优先：列出不属于该类型的成员，算作硬性失败。
- 召回率报告「期望成员出现在前十」的比例，目标 ≥80%。
- 用 VS Code 语言服务的结果作参照，不要求逐条一致。

**导入与跨文件**：
- 样本覆盖：Python 标准库、虚拟环境里的第三方包（含存根）、相对导入、包的再导出；JS/TS 的相对导入、`node_modules`（含 `@types` 和 `exports`）；一个多文件的项目文件夹。
- 验收项：解析正确率、首次解析时延、摘要内存，以及修改另一文件并保存后 ≤1 s 生效。

**交互与安全写入**：
- 在真实窗口里测试：用 Tab、回车、双击接受；用 Esc 关闭；修饰键加方向键；移动光标后接受；组字期间选词；编辑器失焦。
- 覆盖中文与日文、emoji、组合字符、CRLF、文件末尾没有换行、空文档、光标在词中间、折叠区域、大段粘贴、撤销/重做、与搜索高亮共存。
- 测试模块开关组合：每个模块单开、全开、全关。

**工程验收**：
- 按开发流程依次跑相关的 Swift Testing、全量测试、视觉冒烟、真实滚动和输入法操作，最后做同环境资源对照。
- 记录现版与候选版的数据、修复的误判数、仍失败的样本和新增常驻。

## 15. 开工前待确认

以下各项已按建议写进正文。如有不同意见，开工前告知即可。

1. **深层推断的语言**：只做 Python 和 JS/TS；七种静态类型语言只读显式声明，不建它们的标准库类型表（第 8.1 节）。
